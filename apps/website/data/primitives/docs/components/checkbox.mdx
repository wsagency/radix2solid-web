## Anatomy

Import all parts and piece them together.

```jsx
import { Checkbox } from "@wsagency/radix2solid-primitives";
export default () => <Checkbox.Root>
		<Checkbox.Indicator />
	</Checkbox.Root>;
```

## API Reference

### Root

> **Release status:** This local website build uses unpublished source commit `2f8a329afe95c14dbd49810b90744f95a36b775e` (including the Checkbox native required-validation fix from `6395e0dc96f0a912f2a616712e25f289717285aa`). Published npm `@wsagency/radix2solid-primitives@0.1.0-rc.4` remains affected by this required-form-validation issue; no fixed package has been published. The preview below shows a checked control and label inside a form, but it does not demonstrate native form submission or required validation.

For a safety-critical confirmation that depends on the browser blocking submission while a required checkbox is unchecked, avoid the published RC4 Checkbox for that path until a fixed package is published. Use a native input instead:

```html
<form method="post">
  <label>
    <input type="checkbox" required name="confirmDeletion" value="yes" />
    I confirm deletion of this item.
  </label>
  <button type="submit">Delete</button>
</form>
```

Native `required` is browser-side validation only and can be bypassed. The server must independently authorize the request and verify the confirmation before performing a destructive action; a checkbox alone does not secure deletion.

Contains all the parts of a checkbox. An `input` will also render when used within a `form` to ensure events propagate correctly.

## Examples

### Indeterminate

You can set the checkbox to `indeterminate` by taking control of its state.

```tsx line=5,7,8,9,10,11,12,14
import { createSignal } from "solid-js";
import { DividerHorizontalIcon, CheckIcon } from "@wsagency/radix2solid-icons";
import { Checkbox } from "@wsagency/radix2solid-primitives";
export default () => {
  const [checked, setChecked] = createSignal<boolean | "indeterminate">("indeterminate");
  return <>
			<Checkbox.Root aria-label="Select all" checked={checked()} onCheckedChange={setChecked}>
				<Checkbox.Indicator>
					{checked() === "indeterminate" && <DividerHorizontalIcon />}
					{checked() === true && <CheckIcon />}
				</Checkbox.Indicator>
			</Checkbox.Root>

			<button type="button" onClick={() => setChecked(prevIsChecked => prevIsChecked === "indeterminate" ? false : "indeterminate")}>
				Toggle indeterminate
			</button>
		</>;
};
```

### Decoupling the hidden input

By default, `Checkbox.Root` renders a visually hidden `input` for form submission. To recompose, move, or exclude that input, you can build the checkbox from its lower-level parts instead.

> **Important:** These parts are unstable and prefixed with `unstable_`, so their API may change in a future release.

- `Checkbox.unstable_Provider` provides the checkbox state and accepts the form-related props (`name`, `value`, `checked`, `defaultChecked`, `required`, `disabled`, `onCheckedChange`).
- `Checkbox.unstable_Trigger` is the interactive button that wraps `Checkbox.Indicator`.
- `Checkbox.unstable_BubbleInput` is the visually hidden input that `Checkbox.Root` renders by default. Omit it when you don't need form submission.

```jsx
import { Checkbox } from "@wsagency/radix2solid-primitives";
export default () => <Checkbox.unstable_Provider name="terms">
		<Checkbox.unstable_Trigger>
			<Checkbox.Indicator />
		</Checkbox.unstable_Trigger>
		<Checkbox.unstable_BubbleInput />
	</Checkbox.unstable_Provider>;
```
