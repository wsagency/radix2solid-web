# Radix2Solid website implementation

Unofficial native Solid 2 documentation and examples, not the official Radix website or a WorkOS product. Historical original React blog posts, case studies, designs and endorsements retain attribution. Start with the [root bootstrap/install instructions](../../README.md).

The exact inventory is owned by [`coverage-manifest.json`](coverage-manifest.json): 174 MDX documents, 189 routes plus 404, 278 demo files and 119 archives. It preserves 137 original documents and 151 original routes; 37 documents and 38 routes are native-only, including seven Primitives API pages and seven Themes component recipes. Calendar, DatePicker and FileDrop are included in published `0.1.0-rc.4`; their nine current style-variant archives use exact npm dependencies. Original routes were independently observed at the recorded upstream commit; both component indexes have real HTML/Markdown routes.

## Commands from the web root

```sh
export RADIX2SOLID_LIBRARY_SOURCE=/absolute/path/to/radix2solid
node scripts/prepare-library.ts
pnpm install --frozen-lockfile
pnpm --filter @radix-solid/website prepare:public-archives
pnpm build
pnpm typecheck
pnpm --filter @radix-solid/website check:export
pnpm --filter @radix-solid/website check:snippets
pnpm --filter @radix-solid/website check:examples
pnpm --filter @radix-solid/website check:sandboxes
pnpm --filter @radix-solid/website test
pnpm exec playwright test
node apps/website/scripts/check-dev.mjs
pnpm dev
```

The website build now consumes the unpublished local library candidate `0.1.0-rc.5` at source commit `e5305334109c406fa75bc13047c88fe5aae9c733`, with the Solid 2.0.0-rc.19 runtime/compiler tuple and `@solidjs/vite-plugin` 3.0.0-next.52. Solid RC19 and Vite 8.3.3 themselves accept Node `>=22.12.0`; the repository's declared executable support range for its direct Node TypeScript scripts is `>=22.18.0 <23 || >=24.0.0 <25`. Node 23.x is unsupported. The pinned developer runtime remains Node 24.21.0. For local-only validation, set `RADIX2SOLID_LIBRARY_SOURCE` to the absolute path of the source Git repository before running the bootstrap/build. The candidate SHA is not on the remote, so GitHub Actions cannot bootstrap it until an authorized push. This does not claim package publication or a website release. Public package downloads and all 119 registry-based runnable sandboxes remain on published library `0.1.0-rc.4` with the Solid RC15 tuple described below.

Preview is `http://127.0.0.1:4149/`; stop a manual preview before Playwright starts its own, or set `WEBSITE_PREVIEW_PORT` (for example `WEBSITE_PREVIEW_PORT=4150 pnpm exec playwright test`) so the preview server, Playwright `baseURL`/readiness URL and `e2e/website.spec.ts` all use that port instead. Website browser checks retain Chromium, Firefox and WebKit, with no library gallery server.

`check-dev.mjs` is a separate regression check, not a website-serving command or an added CI case. After the existing bootstrap, install/build and Playwright browser setup, it uses the installed Vite and unchanged website configuration on a free local port, checks native homepage controls and Progress-document hydration/theme interactions in Chromium, Firefox and WebKit, then closes its browsers and servers. It targets the development-only ownership guards and SSR link-props regression, not all 151 routes; images remain live, so it is neither fully hermetic nor an image-delivery/Firefox ORB certification.

Trusted local MDX goes through `@mdx-js/mdx` in JSX-preserving mode and the native Solid compiler. String intrinsics and JSX stored in document data are normalized for native ownership; there is no React MDX runtime or bridge. Markdown conversion excludes navigation and hydration markers. MiniSearch retains hierarchical records, prefix/fuzzy matching and heading boosts. Navigation uses ordinary static links, not a custom SPA router.

Cloudflare dispatches all registered non-root page families to the existing Worker for `GET`/`HEAD` negotiation with `Accept: text/markdown` or `text/x-markdown`, returning their actual `.md` twins and `Vary: Accept`; default requests remain HTML and legacy redirects retain precedence. `/` is deliberately not negotiated. JavaScript, CSS, fonts, images and icon downloads keep the native static-assets fast path. The Node suite invokes the Worker directly with real exported assets, so it does not cover Cloudflare's assets-first dispatch: after routing changes, use the installed `pnpm --filter @radix-solid/website exec wrangler dev --local` with current `out/` and check both Accept values over GET and HEAD against the direct Markdown twins.

`check:export` checks exact source, route and archive inventories; HTML/Markdown twins; page/assets/anchors/search targets; indexability (no `noindex` meta or header), privacy and redirects; registered public artifacts; and licensed font hashes in both source and export. Builds clear their own generated `out/` before copying assets, filtering hidden paths relative to `dist/client` so a checkout under a hidden directory still exports its CSS and JavaScript. The five direct package downloads are copied byte-for-byte from SHA-512-pinned registry archives after package identity, safe archive layout and public-content checks; their licenses, NOTICE closure, and Extra icon copies are validated from those same bytes.

`check:snippets` compiles actual native JS/TS/JSX/TSX fences against real declarations/page imports/MDX components, including relative imports and default exports from the actual MDX page. Partial fences inherit documented scope; named neighbouring files come from their real sources, not mocks or ambient `any`. The observed inventory contains 596 native fences across 137 documents, 669 rendered fences with checked annotations and twelve package installation commands. Native registry commands must pin the separately reviewed published RC4 version exactly; local tarball commands must name one of the five exact published archives, and Solid consumer installs must pin the public RC15 tuple. Colors styling resolves actual `@vanilla-extract/css@1.21.3`. `check:examples` builds independent native CSR/SSR fixtures from copied animation/system-appearance guides and exercises transitions, cancellation, disposal, reduced motion and media changes in all three engines. Both commands remove their owned fixtures.

`build-sandboxes.ts` copies the five exact published RC4 package archives into direct `/packages/` exports and reads package licenses, Charts NOTICE and Extra icon assets from those verified tarballs; it never packs `.library` workspace candidates. Before a local website build, explicitly run `pnpm --filter @radix-solid/website prepare:public-archives`; preparation fetches fixed npm registry URLs only when a cache entry is absent and verifies the pinned SHA-512 values, package identity, archive paths and public-content/privacy markers. The normal build reads and verifies the existing cache only; it never fetches or falls back. GitHub Actions caches `.artifacts/public-rc4-tarballs` by the pin file and runs the explicit prepare step before checks. Runnable sandboxes use exact npm `0.1.0-rc.4` dependencies, the exact Solid/web RC.15 tuple, plugin next.50 and Vite 8.3.3 pins, and override Themes' transitive Primitives dependency to the same published version. Exact release-age exceptions cover only those package versions and the Solid toolchain. Charts sandboxes keep its `LICENSE` and `NOTICE`; only Icons Extra variants add that optional package and license. Tailwind entries import their actual stylesheet. Extract a sandbox download, run `pnpm install`, then `pnpm dev` or `pnpm build`.
